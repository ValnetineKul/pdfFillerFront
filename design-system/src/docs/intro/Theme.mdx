# Темы и их поддержка

Для поддержки тем был разработан механизм, который позволяет быстро интегрировать новые темы для нужд проекта.

## Введение

В дизайн-системе существует одна базовая тема, остальные темы являются придаточными.
Придаточные темы, такие как: **"spelet"**, **"winon"**, зависят от основной темы.
Подход простой: все токены, адаптивность и типографика наследуются от основной темы.
Если по дизайну нужно изменить цвета или шрифты, можно точечно перезаписать необходимые параметры,
не копируя весь пресет темы целиком.
На практике, например, нужно перезаписать цвет бренда из общей палитры `core/colors` и в некоторых случаях несколько объектов в файле `semantic/colors`.

### Что такое Preset ?

- **Preset** — это то, чем наполняется **DS**. В папке preset мы можем видеть широкий спектр различных атрибутов дизайн-системы.
  [Ознакомьтесь с документацией как создать preset](https://panda-css.com/docs/customization/presets#creating-a-preset)

Пример структуры:

```
├── preset
│   ├── breakpoints
│   ├── conditions - Список условий которые мы можем переопределить и использовать в более короткой форме в стилях.
│   ├── containerSizes
│   ├── core - Основа для токенов
│   ├── globalStyles - файл глобального CSS
│   ├── keyframes - Для анимаций
│   ├── patterns - Паттерны это репетативные коски стилей которые мы можем переиспользовать
│   ├── recipes - Рецепты для всех компоннетов
│   ├── semantic - Применяемые токены
│   ├── text - Иерархия в типографии
│   └── utilities - кастомные утилитки пример: (изменяем размер иконки)
```

Как видите наименования многих составляющих говорят сами за себя.
Данный список покрывает практически все необходимые сценарии описания тем и стилизацию компонентов.

> При разработке дизайн системы мы ставили задачу максимально широко изучить возможности библиотеки PandaCss, поэтому мы старались использовать практически каждый предоставленный инструмент.
> Хотя эти подходы могу выполнять практически любое требования. Например, такие составляющие как `utilities` и `patterns` иметь только одно-два дополнения которым мы нашли применения, чтобы освоить инструменты.

Далее все эти отдельные составляющие мы соединяем в единый Preset при помощи метода definePreset,
после чего мы готовы включить приготовленный рецепт в центральный конфиг библиотеки.
`panda.config.ts`

```
export default defineConfig({
  presets: [defaultPreset],
```

### Как добавить новую тему ?

Допустим нам требуется добавить тему "XTheme", в которой изменен основной брендовый цвет и заказчик попросил чтобы определенные компоненты были перекрашены.
Хочу вас обрадовать, что всю сложную работу за вас сделает сама библиотека, через конфигурации в `panda.config.ts`.

Для начала необходимо создать папку, в которой будут храниться компоненты, так же как это сделано в папке `preset`.
Мы создаем папку `theme` на том же уровне, что и `preset`.
Внутри папки `theme` создаем подпапку с именем темы, например **"XTheme"**: `/src/theme/xtheme`.
Здесь мы можем скопировать и переопределить только те части, которые необходимо изменить для новой темы, такие как `core/colors -> brand` и цвета для взаимодействия с компонентами.
Цвета, используемые компонентами, находятся в папке `semantic`.
Так как темы могут наследовать токены и другие составляющие из основной темы, нам нужно лишь переопределить небольшую часть, а именно палитру брендовых цветов.

```
export const colors = defineTokens.colors({
  brand: {
    25: { value: '#FFF9E5' },
    50: { value: '#FFF9E5' },
    100: { value: '#FFF4CC' },
    200: { value: '#FFE999' },
    300: { value: '#FFDE66' },
```

После чего мы можем создать токены и применить новые цвета.
Это добавляется в файле `index.ts` который находится рядом в директории.

```
import { defineTokens } from '@pandacss/dev';

import { colors } from './colors';

export const tokens = defineTokens({
  colors,
});
```

То же самое мы должны сделать и с цветами компонента, только в папке `semantic`.

```
export const colors = defineSemanticTokens.colors({
  someComponent: {
    primary: {
      default: {
        border: { value: '{colors.brand.500}' },
        borderHover: { value: '{colors.brand.600}' },
        fg: { value: '{colors.grayLight.800}' },
        fgHover: { value: '{colors.grayLight.800}' },
        bg: { value: '{colors.brand.500}' },
        bgHover: { value: '{colors.brand.600}' },
        bgPressed: { value: '{colors.brand.700}' },
      },
```

И также заводим это в токены только уже семантические, те токены которые используются стилях.

```
import { defineSemanticTokens } from '@pandacss/dev';

import { colors } from './colors';

export const semanticTokens = defineSemanticTokens({
  colors,
});

```

> Важно понимать что мы можем переопределить любой параметр в любой из составляющей.

Далее мы можем собрать пресет для темы и добавить его в конфиг `panda.config.ts`.
Мы добавляем обертку `extend:{}` для того, чтобы новая тема наследовала все токены от основной темы.

```
export const xTheme = {
  tokens,
  semanticTokens,
};

```

А также выполняется [предварительная генерация тем](https://panda-css.com/docs/guides/multiple-themes#pregenerating-themes)

```
export default defineConfig({
  presets: [defaultPreset],
  themes: {
    extend: {
      xTheme,
    },
  },
  staticCss: {
    themes: ['xTheme'],
  },
```

> На данном этапе у нас есть все чтобы мы могли переключить тему в приложении.
> В большинстве случаев требуется дополнительные механизмы переключения. Например, для Storybook существует подходящая функция `withThemeByDataAttribute`, но на проекте `public-client`
> пришлось написать кастомизированную функцию.

### Поддержка

В случае когда мы разрабатываем новый компонент или выявили что компонент не соответствует дизайну из другой темы.

- Первым делом мы можем протестировать изображение компонента при переключении тем в Storybook.
  Если перекраска компонента работает корректно в Storybook.
  Тогда следующим шагом надо найти токены в файлах **DS** которые он применяет для другой темы
  `/src/theme/[theme name]/semantic/color/[search for name of component]`,
  и продублировать их в точно такой же папке на проекте по месту применения.

- Что если и в Storybook компонент не соответствует дизайну. В таком случае обратитесь к дизайнеру, необходимо проработать цвета компонента в рамках другой темы. Далее мы можем составить новые токены для компонента в рамках другой темы.
  И как в первом сценарии мы добавляем их в файл папки `/src/theme/[theme name]` и также дублируем в проекте.
