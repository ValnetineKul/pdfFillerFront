# Структура

```
├── components - Готовые компоненты (здесь приведены только некоторые для примера)
│   ├── @playground - Компоненты для песочницы/прототипирования
│   ├── Accordion - Компонент аккордеона
│   │   ├── base - Базовый компонент
│   │   └── sb - Файлы для Storybook
│   ├── Button - Компонент кнопки
│   ├── ButtonGroup - Группа кнопок
│   └── UNSTABLE_Picker - Компонент выбора (экспериментальный)
│       └── components - Внутренние компоненты для Picker
├── helpers - Вспомогательные функции и утилиты
├── preset - Preset с параметрами дизайн-системы
│   ├── breakpoints - Точки останова для медиа-запросов
│   ├── conditions - Условия для динамических стилей
│   ├── containerSizes - Размеры контейнеров
│   ├── core - Основные токены для базовой темы (цвета, шрифты и т.д.)
│   ├── globalStyles - Глобальные стили CSS
│   ├── keyframes - Определение ключевых кадров для анимаций
│   ├── patterns - Повторяющиеся стили, которые можно переиспользовать
│   ├── recipes - Рецепты для стилей компонентов
│   ├── semantic - Семантические токены (используемые в компонентах)
│   ├── text - Типографические настройки (шрифты, размеры текста)
│   └── utilities - Кастомные утилиты для работы со стилями
├── shared - Общие файлы и ресурсы
│   ├── hooks - Хуки для работы с состояниями
│   ├── styles - Общие стили
│   ├── svg - SVG-иконки
│   └── utils - Общие утилиты и функции
├── system - Включает файлы `mdx` для описания документации Storybook
├── theme - Темы, зависимые от основной темы
│   ├── spelet - Настройки темы "spelet"
│   │   ├── core - Основные токены для темы
│   │   └── semantic - Семантические токены для темы
│   └── winon - Настройки темы "winon"
│       ├── core
│       └── semantic
└── types - Типы и интерфейсы для TypeScript
```

### Описание ключевых папок

- **components**: Содержит готовые UI-компоненты.

- **helpers**: Вспомогательные функции, используемые по всему проекту.

- **preset**: Это набор настроек для **DS**, включающий токены (цвета, шрифты, размеры и т.д.), условия для стилизации, глобальные стили и утилиты для создания повторяющихся стилей.

- **shared**: Содержит общие файлы, которые могут использоваться в разных частях проекта: хуки, стили, SVG-иконки и утилиты.

- **system**: Включает файлы `mdx` для описания документации Storybook

- **theme**: Содержит различные темы проекта. Каждая тема может иметь свои собственные токены (например, брендовые цвета или стили компонентов), которые наследуются от основной темы.

- **types**: Описание типов данных и интерфейсов для работы с TypeScript.

Эта структура помогает поддерживать масштабируемость и гибкость в разработке **DS**, обеспечивая легкое управление компонентами и темами.

### Описание структуры компонентов

```
├── Accordion
│   ├── Accordion.stories.tsx - Файл для демонстрации компонента в Storybook
│   ├── Accordion.tsx - Основная реализация компонента аккордеона
│   ├── index.ts - Точка входа для экспорта компонента
│   ├── base
│   │   └── AccordionItem.tsx - Вложенный компонент для отдельного элемента аккордеона
│   └── sb
│       └── mock.tsx - Моки (вспомогательные данные) для тестирования или демонстрации в Storybook
```

### Описание файлов

- **Accordion.stories.tsx**: Используется для демонстрации и тестирования компонента в Storybook. Этот файл содержит примеры использования и возможные сценарии применения компонента.
- **Accordion.tsx**: Основной файл, содержащий реализацию компонента. Здесь определяется поведение и внешний вид аккордеона.
- **index.ts**: Этот файл экспортирует компонент, что позволяет легко импортировать его в других частях проекта.
- **sb/mock.tsx**: Моки для использования в Storybook. Могут включать фиктивные данные для демонстрации работы компонента в разных состояниях.

- **base/AccordionItem.tsx**: Вложенный компонент, представляющий отдельный элемент аккордеона. Может содержать уникальную логику для управления элементом аккордеона.
  Почему мы поместили этот компонент в отдельную папку base ?
  Если кратко, то компоненты в папке base представляют собой базовые версии компонентов, которые были изменены и улучшены по сравнению с оригинальными версиями из библиотеки **RAC**. Эти компоненты могут включать:

  - Переопределённые или расширенные пропсы (входные параметры), что позволяет компонентам более гибко реагировать на специфические требования проекта.
  - Изменённое управление состоянием, добавляющее дополнительную функциональность или улучшения по сравнению с оригинальными компонентами.
  - Встроенные дополнительные элементы, которые расширяют возможности компонента, добавляя новые функции или изменяя внешний вид и поведение.

> Таким образом, папка base хранит модифицированные версии компонентов, которые служат основой для создания более сложных и кастомизированных решений, специфичных для проекта.

> Важно понимать, что структура компонента может варьироваться в зависимости от его сложности. Иногда достаточно просто добавить стили без переопределения, а в других случаях потребуется создать кастомизированные компоненты и поместить их в папку components. Таким образом, не существует жёстко фиксированной структуры для каждого компонента, но уже есть определённые паттерны, которые стоит использовать.
> Следуйте существующей структуре, названиям и понятиям. Это улучшает Developer Experience (DX) и делает проект понятным для всех участников команды.

- В случае если вам необходимо завести компонент который подобен существующему, например компонент Аккардион устарел и не выполняет требований бизнеса и на основе старого компонента невозможно выполнить данные требования.
  Тогда мы можем завести компонент с припиской `UNSTABLE`. Получится UNSTABLE_Accordion, в таком случае мы стили данного компонента тоже будут иметь префикс `UNSTABLE`.

Эта структура помогает разделить логику и стилизацию компонента на подкомпоненты и упрощает его поддержку и расширение.

### Стили

```
├── src
|   ├── preset - Preset с параметрами дизайн-системы
│   │   ├── recipes - Рецепты для стилей компонентов

```

Мы используем подход, предоставленный библиотекой PandaCSS,
где рецепты для стилей компонентов собираются на уровне пресета, а не внутри отдельных компонентов.
Поэтому все файлы стилей для компонентов находятся в папке `recipes`, чтобы централизовать и упорядочить управление стилями.

Папка `core` содержит базовые токены (переменные), которые используются во всей дизайн системе. Вот её структура:

```
├── core
│ ├── blurs.ts
│ ├── borderWidths.ts
│ ├── colors.ts
│ ├── index.ts
│ ├── radii.ts
│ ├── shadows.ts
│ ├── sizes.ts
│ ├── spacing.ts
│ └── typography.ts
```

Пример токена цвета в `core`

`black: { value: '#000' },`

В папке `semantic` мы можем переопределять или использовать токены из папки `core`.
Далее именно значения из папки `semantic` используются в написании стилей и паттернах.

```
├── semantic
│ ├── aspectRatio.ts
│ ├── colors.ts
│ ├── index.ts
│ ├── radii.ts
│ ├── shadows.ts
│ ├── sizes.ts
│ ├── spacing.ts
│ └── zIndex.ts
```

Пример использования токена цвета из `core` в `semantic`

```
text: {
  onBrand: { value: '{colors.black}' },
},
```
